# User Interface Plan

## Overview
The Smart Virtual Assistant will provide a simple
and user-friendly interface for students to ask
questions about campus offices and opening hours.

## Target Users
- Students who need information about campus offices.
- New students who are unfamiliar with campus services.

## Planned Features
- A text input field for entering questions.
- A submit button to send the question.
- A response area displaying the assistant's answer.
- Clear and accessible instructions for users.

## User Interaction Flow
1. The user opens the assistant interface.
2. The user types a question, such as
   "Where is the IT helpdesk?"
3. The user submits the question.
4. The assistant displays the relevant office information.

## Future Implementation
A lightweight Python UI framework such as Streamlit
or Gradio may be considered in later development stages.
The final choice has not yet been made.

## Current Status
This document describes the proposed user interface.
The actual UI has not yet been implemented as part of Lab 1.

## Preview the Chat Interface

The chat interface is a static HTML prototype located at
`ui/index.html`. No backend connection is required.

### How to Preview

1. Open the project folder.
2. Navigate to the `ui/` directory.
3. Open `index.html` in a web browser.

Alternatively, open the project in Visual Studio Code and
use a local preview extension if available.

### Prototype Limitations

- The question input and submit button are displayed.
- Submitting a question only displays a status message.
- Answers are not generated by the backend.
- The example response is illustrative sample data,
  not verified official university information.

## Answer Presentation and Information Sources

### 1. Answer Format

Assistant responses should be concise, readable, and easy for students to understand.

When office information is available, display:

- **Office name:** The name of the relevant office.
- **Room:** The building or room number, when available.
- **Opening hours:** The days and times when the office is open.
- **Source:** The dataset, document, or official page used to answer the question, when available.

Use clear labels and separate lines to make the information easy to read.

### 2. Example of a Successful Response

**Question:** Where is the IT helpdesk?

**Answer:**
IT Helpdesk: room E.005, open Mon-Fri 08:00-17:00.

**Source:** Sample office data.

**Note:** This is an illustrative example. The location and opening hours must be checked against official university information before being presented as verified facts.

### 3. Identifying Information Sources

The interface should identify the source of an answer whenever reliable source information is available.

- Display a clear label such as `Source:` or `Information source:`.
- Identify the relevant dataset, document, or official webpage.
- Distinguish sample data from verified official information.
- Do not claim that information is officially verified unless it has been checked against an authoritative source.
- Do not invent source names, URLs, or citations.

If the source is unavailable, state that the source could not be identified instead of making one up.

### 4. Unknown Answers

If the assistant cannot find sufficient information to answer a question, it should clearly tell the user.

**Example:**

**Answer:** Sorry, I could not find reliable information to answer your question. Please check the official university website or contact the relevant office.

The assistant should not invent office locations, room numbers, opening hours, or information sources.

### 5. Sample Data and Official Information

Sample data may be used for development, testing, and demonstrations. It must be clearly labelled as sample or illustrative data.

Information should only be described as verified official information when it has been checked against an authoritative source.

The interface and its documentation should make this distinction clear so users do not mistake demonstration content for confirmed university information.
